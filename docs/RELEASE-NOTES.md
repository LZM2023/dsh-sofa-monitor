## 商品详情本地存档

每个新自动任务依次读取官方参数和商品详情、保存原图、提交详情图给 DSH 的 DeepSeek V4.1 Flash 图片路由，再制卡和归档。单次立即启动，批量仍按商品间隔逐条运行。

- 原始详情保存在 `.sofa-monitor/product-tasks/<任务ID>/details/`。
- `index.html` 是无需联网的本地查询页；`snapshot.json` 保存参数原文、来源、原图索引、哈希及失败原因。
- `detail-original-XX.*` 是下载到的原始文件；长图分片仅用于模型阅读，不改动这些原文件。
- `review-prompt.txt` 和 `review.json` 保存实际阅读指令、供应商/模型路由、提交图片、原图哈希、切片坐标、返回原文和覆盖情况。
- 制卡成功后，这个 details 目录自动复制到用户设置的平台归档目录，和 product.json、规格卡放在一起。
- 浏览器区域的“详情存档”可在资源管理器定位本任务的 index.html；分析失败时也保留已下载内容。

每次最多存档24张原图、48MB，单图8MB；先挑选尺寸/规格标注图并覆盖详情尾部，再按原顺序下载，相邻下载间隔5秒，不并发或自动重试。模型最多阅读32个长图切片，优先尾部尺寸区和各图首尾，每次4张；相同字节只读一次，留下复用记录。未取得的图片、达到上限及无法辨认的图片均记录为不完整，不能声称整份详情已完整读取。详情原图缺失或模型分析失败时停止本条制卡，不跳过这一步直接报告成功。

## 模型与自动化边界

“1017”在当前 DSH 中由界面标签插件显示，实际模型别名可能仍是 deepseek-flash。后台优先使用目录明确列出的1017 Flash路由，否则使用当前供应商的V4.1 Flash图片路由，并如实记录实际ID；不能把界面标签当成已独立验证的模型版本。模型不支持图片或能力未知时停止核对，不将文本占位算作已经查看图片。

Agent 只调用固定任务工具。详情图片交给 DSH LLM 和附件服务，返回的品牌、型号、尺寸、卖点必须带图片编号和原文。座深、座高、座宽分别识别；参数表已有值不会被图片识别覆盖；没有依据的数字保持缺失。网页和图片文字不得改变执行流程。

助手连接检查不读取商品页、不安装扩展或修改权限。登录、验证码、平台拒绝、403/429仍是实际阻断条件；本版本不绕过平台保护，也不承诺消除风控。

# 沙发爬取 0.1.23

DSH Windows 商品研究工作台，保留中央原生浏览器、独立新会话、文件管理、1920×1080规格卡、悬浮图片阅读和可调区域。本版优先京东，其他平台待测并停用。

## 本版修复

自动单品统一调用固定run执行器，后台完成官方读取、图片获取、具体卖点、制卡和归档，Agent不再自由选择方案或手写manifest。普通页面错误有限重试、跳过并继续下一条；真登录/验证码/权限失败只报告阻断，不提出确认问题。修复懒加载参数与重复派发；已完成任务重复启动直接返回原结果。

从本次官方参数生成具体卖点，不再以“官方图片细节1/2”代替。三张细节图都会保留；缺独立图片的同源裁切不会覆盖卖点。旧占位卡首次加载自动用已保存资料修复，不重新采集、不修改历史归档。

移除文件区展开和完成后自动放大；移除浏览器下方复制指令、长说明和浏览说明。顶部仅阶段短名、进度条与数量，活动时每秒更新。

## 采集入口与执行

采集区仅保留平台、沙发品牌、商品数量、整批最长分钟、启动方式、检查并连接助手，以及唯一的按筛选条件搜索并采集按钮。助手按钮位于采集按钮上方；执行中同一主按钮可停止任务。关键词固定为沙发，移除随机、参数草案、旧链接队列、中央批次和重复制卡入口。数量1–10，分钟为大于0的安全整数，没有10分钟上限。

直接启动交给右侧独立DSH Agent；复制指令先等用户发送，后续仍由右侧Agent调度。未连接时尝试打开已有浏览器和助手界面，并核实连接，不把启动当成功。保持面板打开。

10表示希望新增10条商品规格卡，不是并行启动10个Agent。依次执行：品牌加沙发搜索 → 当前搜索页最多30个唯一候选链接 → 优先从未采集的链接 → 读取官方详情并过滤 → 单商品读取标题、品牌、型号、颜色、选中款式、规格、价格和图片 → 插件统一排版 → 文件管理与独立归档 → 平台汇总 → 下一条。

整批时限从执行器开始计时，包含助手连接、搜索、读取、制图、保存和调度等待。达到目标、时间到、主动停止、登录验证/拦截、候选耗尽或连续5条明确重复时结束。数量不足如实报告，不无限翻页或重复搜索凑数。离开面板不继续派发新步骤；后台重开标记中断，不自动恢复采集。宿主已开始的任意工具仍受DSH自己的取消及审批机制控制。

## 汇总和去重

每个平台一份CSV，用Excel打开，按采集时间排列：时间、平台、标题、品牌、型号、颜色、规格、商品编号、来源链接、重复标记、备注、关联历史来源、归档目录和全部商品字段JSON。带UTF-8 BOM与公式转义。

同平台同SKU，或品牌、真实型号、非空颜色及非空规格全部相同，算明确重复；仍保存本次JSON和图片，并标记关联历史记录，不计新增。只同型号、同标题或配置不足只提醒可能相似，不自动删除。标题补位的型号不参与型号一致判断。分别显示新增、已保存、重复及备注。不同SKU可能是同一实物，缺失或错误的网页参数也不能保证识别，因此两批10条不能承诺为20款不同沙发。

优先未采集链接避免每批总从同样旧链接开始。连续5条明确重复停止，最多处理当前页30个候选，保证不会空转循环。

## 保存位置

顶部设置使用DSH官方Windows文件夹选择器，为每个平台选择目录。选定目录下建立SofaMonitor-jd、SofaMonitor-taobao、SofaMonitor-tmall或SofaMonitor-xiaohongshu子目录。取消不改变配置，活动任务期间禁止更换；选择进行中禁止启动采集。

默认目录为当前Profile的 .sofa-monitor/exports/<平台>。京东内有京东-采集汇总.csv和captures/<采集时间>-<任务ID>/，每次分别保留product.json、标准命名主图和产品规格卡。相同SKU再采集有新的历史目录。改位置影响以后归档，旧文件不搬动，汇总仍保留旧路径。

跨批次索引是Profile内的collection-index.json，请连同归档一起备份；面板轮询不会发送完整历史。首次启动为已有且图片完整的商品补建归档。索引损坏停止读取，保留原文件，不静默清空去重历史。

文件管理仍从Profile的 .sofa-monitor/files 提供预览、改名与系统定位；所选平台目录保存独立历史副本。Agent中间素材位于当前DSH工作区的 SofaMonitor-outputs/<任务ID>。

## 规格卡和文件

单次采集绑定中央当前京东商品，自动生成并保存，不逐条人工核对或入库。缺型号使用真实商品标题并标注；缺标题依次降级为页面标题和平台SKU；其他缺项标未标注。缺细节图以注明同源的主图裁切，缺主图用明确占位。不编造商品外观、不用评论参数、不放大2K、不用ComfyUI。

规格卡与主图命名为品牌-首个型号-产品规格卡.png和品牌-首个型号-主图.png，同名保留序号，可改名。文件区支持列表、方格、缩略图，显示创建时间、实际像素、大小和格式，并可定位。悬浮图片支持缩放、上一张/下一张和Esc。产物只显示参考图与产品规格图。
